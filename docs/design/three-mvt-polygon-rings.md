# Three.js MVT — ポリゴンリング分類（土地利用道路の欠け）

## 事象

3D Viewer（Three.js）で、京都駅周辺など **タイル境界付近**の土地利用（`luse-2025`）において、**道路用地**（橙色）だけが欠ける・細い欠片だけ残ることがあった。

代表例: **z16 / 57481 / 25960**（地点は [kyoto-z16-gate.md](./kyoto-z16-gate.md) と同系）。

2D MapLibre では同タイル・同属性で問題になりにくい。

## 原因

MVT の Polygon（type 3）は `loadGeometry()` で **複数リング**の配列になる。仕様上、**外周 1 本＋穴 0 本以上**が正しいが、**タイルクリップ後**は次のような並びになり得る。

- 面積の大きい **本体**と、境界上の **小さな外周断片**が、**同じ向き（符号付き面積が同符号）**のリングとして連続する
- その後に、**反対向き**のリング（真の穴）が続く

初期実装は **「0 番＝外周、1 番以降＝すべて穴」** と決め打ちしていた。  
タイル 57481/25960 の道路地物 `luse_26483b76-…` では、20 頂点の小リングを外周、**798 頂点の道路本体を穴**と解釈し、ほぼ全面が抜けていた。隣タイル 57481/25961 では外周が 618 頂点側に来るため、**タイルごとに症状が変わる**。

これは **データ欠損ではなく、Three 側の三角形化前処理の誤り**である。

## 対処（実装）

| 項目 | 内容 |
| --- | --- |
| モジュール | `web/shared/mvt/polygon-rings.js` — `classifyPolygonRings()` |
| 方針 | Mapbox **geojson-vt** の `classifyRings` と同様、**符号付き面積**で外周リングを切り替え、外周＋穴のグループに分割してから `ShapeGeometry` を生成 |
| 利用箇所 | `web/viewers/three/js/services/mvt-mesh.js` |

タイル境界の **クリップ平面**（`mvt-mesh.js`）は従来どおり。クリップで各タイルの表示範囲を切り、隣タイルの断片と合成する。

## 混同しやすい点（重複排除）

- **タイル跨ぎの同一 `gml_id`** は MVT では普通に起きる（1 地物の境界分割）。**描画のために gml_id で 1 枚に潰す処理は不要**であり、欠けの原因になり得る（Three からは削除済み）。
- **タイル内**の同一 ID 二重は `dedupeMvtFeatures` で保険（京都 z16 では実測ほぼ 0）。
- **MapLibre クリック照会**の重複排除は `web/shared/mvt/rendered-feature-dedup.js`（描画とは別）。

## 手動確認

1. Three Viewer をハードリロード、原点を京都駅付近、MVT 表示距離まで寄る
2. 土地利用 ON — **57481/25960** 付近の橙色（`luse_class` に「道路用地」等）が途切れないこと
3. 2D と並べて色・範囲が大きく乖離しないこと（完全一致はタイルクリップ・透明度の差で許容）

## B.2 道路用地の地形ドレープ（2026-10-11）

| 項目 | 内容 |
| --- | --- |
| 対象 | **`luse-2025` の全ポリゴン**（重さ確認用に道路だけに限定しない第一版） |
| 標高 | ちずうつし `sampleDisplayedTerrainLocalY`（読込済み DEM グリッドのバイリニア補間） |
| メッシュ | 従来どおり `ShapeGeometry` で三角分割 → 各頂点の Y をサンプル標高 **+ 2 m** |
| 再描画 | 地形タイル確定時に MVT を `clearTiles` して再取得（ドレープ用 DEM が揃ってから） |
| モジュール | `mvt-drape.js` / `mvt-mesh.js` / `scene-adapter.js` |

地形 OFF または DEM 未読込の頂点はフラット高さ（1.2 m）のまま。
