## 合意サマリ

| 項目 | 内容 |
| --- | --- |
| 成果物の優先 | **Even G2 最優先**。2D Viewer は検証基盤。3D Viewer は条件付きだが **最低限は動作させる**。 |
| 対象地域 | **京都駅**を初期原点（緯度経度は別途指定。**小数点以下 3 桁**の数値で固定）。**京都・東京の両方**で動作確認する。 |
| データ年度 | **2025 年度 MVT** を基本。配布状況は `web/data/snapshot/plateau-datasets-2025.json`（ビルド生成・gitignore）を見て最終判断。 |
| zoom 16 | 原本相当の **第一候補**。東京は z16 が最大解像度であることを確認済み。**京都も同様に実データ検証してから確定**し、本格開発の前にゲートを通す。 |
| 道路 | `uro_orgLandUse === "道路"`。`tran-lod1` は道路定義に使わない。 |
| 描画の重なり（仮） | **地形 → 道路 → 都市計画**（都市計画は表示切替／半透明）。色は仮決めで入れて調整。 |
| codelist | 主に **用途地域（USE_DISTRICT）・建ぺい率・容積率**。土地利用（LANDUSE）は変換必須はなさそう。**`city_name` は保持**（専用パースはしない）。 |
| 建物 | **2D**：MVT（`bldg_dm` 等）を調査して採否。**3D / G2**：**ちずうつし方式の GeoJSON** で描画する方針。 |
| Ortho | 地理院タイルへ **先に差し替えて表示可否を確認**する。 |
| 座標 | **JGD2011 平面直角第 VI 系（EPSG:6674）**。描画ローカルは **ちずうつし（kuwaya-geo）現行方針**に合わせる。 |
| コード構成 | 大規模再編は避け **`web/shared/mvt/` 拡張**。Even G2 用パッケージビルドは **静的 Web とは別扱い**。 |
| G2 更新 | **方位変化だけではデータ再取得しない**。再描画トリガーは **ちずうつし同等**を目安。3D 更新は **連続 30/60fps ではなくイベント駆動**（目安 **1〜10 fps** が望ましい）。 |
| 2D と G2 | **並行開発可**。用途地域の **クリッピングは準必須**（方式確定後にドキュメント化）。一貫性は形ができた段階で一度確認し、以降は並行で見る。 |
| 証跡 | **スクリーンショットは必須にしない**。ログ・短いメモは適宜。変更は **確認時にユーザー側で Git コミット**。 |
| ドキュメント | **無駄なコメント・記述は削除**する（スコープ外プロダクト等）。 |

### 次のアクション（合意に基づく）

1. 京都府の市区町村 GeoJSON を出力し、内容を開発側で共有・通知する。
2. 京都における **zoom 16 MVT** の実データ検証（東京と同様の観点で合格基準を定義）。
3. 地理院 **Ortho 差し替え**で京都駅周辺の描画確認。
4. Even G2：**静止画生成 → 実機送信**（[even-g2-3d-summary.md](even-g2-3d-summary.md) 検証 1〜3）を先行。

## 2. 地域・データ・索引

### 2.1 地理範囲

| 項目 | 合意 |
| --- | --- |
| 初期表示 | **京都駅**周辺。原点の緯度経度は **小数点以下 3 桁**で別途指定。 |
| 京都索引・市区町村データ | GeoJSON 等を **出力後、開発者側で内容を共有・通知**。manifest / z12 索引はそれに基づいて拡張。 |
| 東京＋埼玉索引 | **維持**。京都と **両方**で動作確認する。 |

### 2.2 MVT・ズーム

| 項目 | 合意 |
| --- | --- |
| 年度・取得 | **2025 年度 MVT**。カタログは `data/snapshot/plateau-datasets-2025.json` を参照し、配布状況で微調整可。 |
| `luse` / `USE_DISTRICT` | 上記と同じく **2025 年度 MVT** から取得。CityGML 側の識別前提は `architecture_new.md` §2.5。 |
| zoom 16 | 検証して確定。**本格開発の前に京都で確認**。東京は z16 最大解像度を確認済み — 京都も同様の確認後に合格基準を文書化。 |
| 固定サンプル（z/x/y 等） | 京都検証の進行に合わせて固定。年度・データセット名は上記スナップショットに従う。 |

### 2.3 道路・属性・codelist

| 項目 | 合意 |
| --- | --- |
| 道路定義 | `uro_orgLandUse === "道路"`。`tran-lod1` は今回の道路定義に **使わない**。 |
| 表示（仮） | 重なり順：**地形 → 道路 → 都市計画**（都市計画は ON/OFF・半透明）。色は仮置きで調整。 |

### 2.4 標高・Ortho・建物

| 項目 | 合意 |
| --- | --- |

| 建物 | 2D は MVT 調査の結果で判断。3D / G2 は **ちずうつし GeoJSON 取得・描画**を採用。必達には含めない（性能・調査次第）。 |

## 3. 座標・共通処理・アーキテクチャ

| 項目 | 合意 |
| --- | --- |
| 平面直角座標 | **EPSG:6674** — 確定。 |
| 描画ローカル座標 | **ちずうつし現行方針**でよい（京都駅での検証記録は実装時に残す）。 |
| 共通化の境界 | データ取得・索引・デコード・属性・標高・幾何を共通化、UI/描画は分離 — **現行方針**。細部は必要なら短く整理。 |
| ディレクトリ | **`web/shared/mvt/` 拡張**、大規模再編なし。Even G2 は別ディレクトリ／パッケージ想定。 |
| ビルド境界 | 静的 Web はビルド不要、**Even G2 パッケージ用ビルドは別扱い**。 |

## 4. Even G2・SDK・実機

| 項目 | 合意 |
| --- | --- |
| Even Hub SDK | 実装時点の **公式推奨・最新安定版**と推奨構成。 |
| プライベート配布・実機 | **準必須**として進める（権限・手順は SDK 確認）。 |
| 動作ログ | GPS・方位・通信・エラー等を **画面に表示**（開発確認用）。 |
| 方位 | SDK・実機で API 等を確認。未取得時は **真北を上**。 |
| 再取得・再描画 | **方位のみでは MVT/標高の再 fetch しない**。トリガーは **ちずうつし同等**。 |
| レイアウト | 標高・用途地域・建ぺい・容積・道路を簡潔表示。3D は **単一の小さな画像コンテナ**から（even-g2-3d-summary）。 |

---

## 5. 表示・3D・性能（Even G2）

| 項目 | 合意 |
| --- | --- |
| 3D 方式 | スマホ WebView で描画 → 画像化 → Even Hub SDK → G2。**G2 上 WebGL はしない** — 第一候補で合意。 |
| フレームレート | 連続 3D は目標にしない。**1〜10 fps 程度**出せれば望ましい（イベント駆動）。 |
| 性能 KPI | **転送・表示更新を最優先**。具体上限は実測後に記載。 |
| フォールバック | Three.js で不足なら **Canvas 2D ワイヤー／簡略図**（even-g2-3d-summary）。 |
| 3D Viewer との関係 | **データ・幾何は共有**、G2 向け描画・UI は **独立**。 |
| 実機前の確定 | 第一候補の実機検証後に設計を確定。他にゲート文書があればそのとき確認。 |

検証順序の詳細は [even-g2-3d-summary.md](even-g2-3d-summary.md) の表（静止画 → 送信 → 性能 → GPS → 方位 → 建物任意）。
